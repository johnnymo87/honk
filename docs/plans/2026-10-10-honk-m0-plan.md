# honk M0 (scaffold + spike) Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or
> subagent-driven-development) to implement this plan task-by-task.

**Goal:** Measure the goose 1.54 ACP behaviors the relay design depends on, with a
human go/no-go on goose itself, and record wire fixtures. The output is a findings doc
that confirms or amends the design before M1 is planned.

**Architecture:** An HTTP+SSE-only upstream client library, `honk-upstream` (raw
`serde_json::Value`, explicit reattach / 409-retry / DELETE / hard-drop, frame
recording). It is written now because M1's honkd needs exactly this. The official
`agent-client-protocol-http` `HttpClient` can't be used: its `Drop` sends DELETE
(`client.rs:680-683`), and it can't attach to an existing connection id. The probes
are `#[ignore]`-gated integration tests against an **isolated** `goose serve`, so
they become the design's §7 live-smoke suite. WebSocket gets a single manual check.
Its behavior is already settled from source.

**Tech Stack:** Rust 1.99.0 (goose's pin), tokio, reqwest + `eventsource-stream`,
serde_json, anyhow. Nix flake dev shell (oxalica rust-overlay). GitHub Actions.

**Read first:** `docs/plans/2026-10-10-honk-design.md` §3, §5, §6, §8.

**Review record:** revised 2026-10-10 after adversarial and oracle review. The review
found approve-mode false negatives, sandbox isolation holes, a missing
same-connection reconcile probe, and an untested reattach 409 window and frame loss.

## Ground rules

- **The production goose is off-limits.** It listens on 127.0.0.1:4080, and another
  daemon uses it. Probes talk only to the sandbox (port 4180). `honk-upstream`
  refuses port 4080. Nothing in M0 runs `goose acp` or `goose` without
  `GOOSE_PATH_ROOT` set to the sandbox.
- **Permission mode is set per session, never per process.** Long-turn probes call
  `session/set_mode` with `auto` right after `session/new`. Only P4 and P5c use
  `approve`. Every probe fails loudly if it receives a `session/request_permission`
  it didn't expect, so it can't misread "blocked on a prompt" as "turn died".
- **Standard long turn:** `Run the shell command "sleep 40 && echo done", then reply
  with only the word FINISHED.` For streaming-heavy probes, use the **streaming turn**:
  `Write a 60-line markdown document about tides, including a 5-row table, then reply
  FINISHED.`
- **Model:** the cheapest Claude model cfp routes (a Haiku-class model if available),
  set via `session/set_config_option {configId:"model"}`; record the exact name in the
  findings. Otherwise use the configured default with the shortest prompts that work.
- **Fixtures:** `fixtures/goose-1.54.0-patched.2/<probe>/<ts>.jsonl`. Each line is
  `{"t_ms","dir":"in|out|marker","stream":"post|conn|session:<id>","http_status"?,
  "frame"?,"note"?}`, and markers record drops, reattaches, 409s and restarts.
  - **This repo is public.** The redactor replaces the secret, `$HOME` paths, the GCP
    project id, any hostnames, and any org names that appear in config. Review every
    fixture diff by eye before pushing.
- **Long waits:** the bash tool times out after 120 s. Run each probe test as a
  `systemd-run --user` unit, or keep each wait under 100 s and poll.
- **Record the verdict as you go** in `docs/spike/m0-findings.md`, with the probe's
  decision-rule outcome and the fixture path.

## Wire facts (verified from `agent-client-protocol-http` 2.2.0 and goose v1.54.0 source)

| Fact | Source |
|---|---|
| `POST /acp` `initialize` with no `Acp-Connection-Id` → `200` JSON reply with the id in the `Acp-Connection-Id` response header | `http_server.rs:72-135` |
| Later POSTs carry `Acp-Connection-Id` (and `Acp-Session-Id` for 10 session-scoped methods, else `400`) → `202` | `http_server.rs:183`, `protocol.rs:10-24` |
| A reply goes to the stream of the session named in the request (params or header). `session/new` replies → **connection** stream. `session/prompt`, `session/load`, `_goose/unstable/session/export` replies and `request_permission` → **that session's** stream | `connection.rs:335-367`, `http_server.rs:241-275` |
| `GET /acp` with `Accept: text/event-stream` subscribes: no session header = connection stream, with `Acp-Session-Id` = session stream. Second subscriber → `409`. Keepalive is an **empty `data:` every 15 s**, which the parser must skip | `http_server.rs:327-416` |
| Mailboxes are unbounded and queue frames while nothing is subscribed. When the stream is dropped, the receiver goes back to its slot, but only once axum notices (possibly at the next write) | `connection.rs:37-60, 92-104` |
| A frame is taken from the queue before it is written, so delivery is at-most-once across a dying socket | `http_server.rs:366-368` |
| Nothing reaps connections: they end on DELETE, agent-task end, or failed initialize. DELETE and WS close both call `shutdown()`, which cancels the run | `http_server.rs:417-430`, `websocket_server.rs:73-76`, `server.rs:265-279` |
| After a goose restart, stale connection ids get `404` on POST and GET | `http_server.rs:140-141, 347-348` |
| Auth: `X-Secret-Key` header | goose `transport/auth.rs:20-31` |
| `session/cancel` is a notification. `session/set_mode` is per session and persisted. Steer run id is at `_meta.goose.activeRunId` | `dispatch.rs:143`, `server.rs:2521-2537, 1981-1990` |
| `GOOSE_PATH_ROOT` is **silently ignored unless absolute**. Plugin hooks load from the process **cwd** | `config/paths.rs` `validated_path_root`, `agent.rs:485` |

### Task 4: `honk-upstream` HTTP+SSE client with recording

**Files:**
- Modify: `crates/honk-upstream/src/lib.rs`
- Create: `src/{conn.rs,sse.rs,record.rs,redact.rs}`

TDD the pure parts first (unit tests, no goose):
1. `redact.rs`. Write the test first:
   ```rust
   let r = Redactor::new(vec![("s3cret".into(), "<SECRET>".into()),
                              ("/home/dev".into(), "$HOME".into())]);
   assert_eq!(r.apply(json!({"a":"s3cret","cwd":"/home/dev/x","n":1})),
              json!({"a":"<SECRET>","cwd":"$HOME/x","n":1}));
   ```
   Implement it as a recursive walk over the JSON strings.
2. `sse.rs`. Test that an SSE byte stream containing an empty keepalive `data:`, a
   JSON frame, and a frame split across chunks yields exactly the JSON values. Then
   implement on top of `eventsource-stream`.
3. `record.rs`: a JSONL writer using the fixture line schema from the Ground rules.
   Test one round trip.

Then implement `Upstream` in `conn.rs` (integration-tested by the probes):
```rust
pub struct Upstream { /* url, secret, http, conn_id, streams: HashMap<StreamKey, JoinHandle>, rx, rec */ }
impl Upstream {
    pub async fn initialize(url, secret, rec) -> Result<Self>;          // POST, store conn id
    pub async fn request(&self, method, params, session: Option<&str>) -> Result<Value /*id*/>;
    pub async fn notify(&self, method, params, session: Option<&str>) -> Result<()>;
    pub async fn respond(&self, id: Value, result: Value, session: Option<&str>) -> Result<()>;
    pub async fn subscribe(&mut self, session: Option<&str>) -> Result<()>; // GET; on 409 retry with backoff, recording each 409 with its timestamp
    pub async fn next(&mut self, timeout: Duration) -> Result<Option<(StreamKey, Value)>>;
    pub fn hard_drop(&mut self);                                          // abort SSE tasks, no DELETE
    pub fn resume(conn_id, url, secret, rec) -> Self;                     // reuse an existing id
    pub async fn delete(self) -> Result<StatusCode>;
}
```
Every inbound and outbound frame, HTTP status, drop, reattach and 409 is written to
the recorder. `guard_url` is called in `initialize` and `resume`.

**Smoke test** `tests/live_smoke.rs`, marked `#[ignore]`: initialize, subscribe the
connection stream, `session/new {cwd: <tmp>, mcpServers: []}`. Assert the reply
arrived on the **connection** stream. Then subscribe to the session stream, call
`set_mode auto`, set the model, and run a one-word prompt.
Run it with `HONK_GOOSE_SECRET=... cargo test -p honk-upstream --test live_smoke --
--ignored`.

**Commit:** `upstream: http+sse acp client with reattach and recording`.

### Task 6: P2, HTTP disconnect, reattach window and frame loss

**File:** `crates/honk-upstream/tests/p2_disconnect.rs` (`#[ignore]`).

Three variants, each on a fresh session with `auto` mode:
- **P2a, quiet drop.** Use the long turn. Wait for the shell `tool_call`, then
  `hard_drop`. **Immediately** `resume` and `subscribe` both streams, retrying on 409,
  and record how long the 409 window lasted. Read until the `session/prompt` reply
  arrives. Then export, and check that `FINISHED` is present.
- **P2b, drop while streaming.** Use the streaming turn. Drop after about 20
  `agent_message_chunk`s, then reattach. Count the chunks received before and after
  the drop and compare the concatenated text with the exported final message.
  Record how many frames were lost, and whether the prompt reply was lost.
- **P2c, long gap.** Same as P2a, but wait 10 minutes before reattaching. Run it in
  parallel with other probes on its own session. It checks that no reaper exists.

**Decision rules:**
- The turn survives in P2a and P2c → design §6 holds as written.
- The turn doesn't survive → amend the design to the WS-plus-drain fallback.
- 409 window > 0 → honkd's reattach must retry on 409 with backoff. Record the
  maximum window seen.
- Any frame lost in P2b → honkd **must** reconcile after every reattach, via the
  same-connection reload (P3). It must not trust the stream. If the prompt reply can
  be lost, honkd must detect turn end from `session_info_update` or export, and must
  not wait on the reply alone.

**Commit:** test plus fixtures, with message `probe(P2): http disconnect, reattach window, frame loss`.

### Task 8: P3, same-connection reload mid-run (honkd's reconcile path)

**File:** `tests/p3_reconcile.rs` (`#[ignore]`).

1. Start the streaming turn on connection A. `hard_drop`, then `resume` A.
2. While the run is **still active**, send `session/load` on **A**, passing the cwd
   stored in `session/list` and no `replayTail`. Record:
   - success or error;
   - the replay frames, then every live frame that follows;
   - whether the same in-memory agent is reused (a second set of extension
     processes appearing, `ps --ppid <goose pid>`, means it wasn't).
3. Rebuild the transcript from replay plus subsequent live frames, and compare it
   with the export after the turn ends. Look for duplicated text, missing text, and
   order.
4. Repeat step 2 passing a **different** cwd, and confirm with `session/list` that
   the stored cwd was rewritten.

**Decision rules:**
- The reload is rejected during a run → honkd waits for turn end (detected from
  `session_info_update` or export polling) before reconciling. Amend design §5.
- Replay plus live gives duplicates → the reconcile emits a reset and suppresses live
  deltas for the in-flight message until the turn ends, then reconciles again.
- A second agent is spawned → never reload on a held connection mid-run.

**Commit:** `probe(P3): same-connection reload mid-run`.

### Task 9: P4, pending permission with no listener (approve mode)

**File:** `tests/p4_pending.rs` (`#[ignore]`).

1. HTTP: set the session to `approve`, then prompt something that runs a shell
   command. When `request_permission` arrives, `hard_drop` without answering. Wait
   90 s, then `resume`. Is the request redelivered? Answer `allow_once`. Does the
   tool run and the turn finish?
2. Lost-permission case: drop the socket so the permission frame is mid-write. Do
   this best-effort, by dropping as soon as the `tool_call` appears. If it's lost,
   does `session/load` on the same connection re-send it?
3. After a WS-style cancel (DELETE, then a fresh connection, then `session/load`),
   is the persisted permission re-sent? **Answer it**, and record whether any tool
   actually executes. Run this once with the state machine off and once with it on
   (`_meta` on the prompt, `server.rs:2325`).
4. Elicitation forms: mark "untested" unless the sandbox has an eliciting MCP. Don't
   build one in M0.

**Decision rules:**
- Redelivery works → honkd holds pending requests with no viewer, as designed.
- An answer after a reload executes nothing → honkd must surface "request is stale,
  re-prompt" to viewers instead of showing an answerable dialog.

**Commit:** `probe(P4): pending permission with no listener`.

### Task 10: P5, cancel, steer and goose restart

**File:** `tests/p5_control.rs` (`#[ignore]`).

- **P5a.** Cancel the long turn with the `session/cancel` notification, sent first
  from A and then from a second connection B. Record the latency to
  `stopReason: cancelled`.
- **P5b.** Send `$/cancel_request` for the in-flight `session/prompt` id. Is it
  honored? If so, honkd must never drop a prompt handle; record that as a rule for
  M1's client code.
- **P5c.** Cancel while parked on a permission request (`approve`). Does the run
  stop without an answer? The source predicts it doesn't. If so, honkd's Cancel must
  also reject outstanding requests, which design §5 already says.
- **P5d.** Steer that is accepted and then dropped: steer just before the turn ends.
  Does the steer reply succeed while the text is never consumed? Check via export. If
  so, honkd must confirm steer consumption, using the next user message in the
  stream or export, and fall back to queueing.
- **P5e.** goose restart mid-turn:
  `systemctl --user restart honk-goose-sandbox` during the long turn. Record:
  - 404 on POST and GET with the old connection id;
  - what export shows (a persisted user message with no reply?);
  - what a fresh `session/load` re-sends.
  This sets honkd's reconnect behavior.
- After every cancel, export the session and record whether the user message was
  persisted without a run.
