# honk M1 (honkd relay) Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or
> subagent-driven-development) to implement this plan task-by-task.

**Goal:** Build `honkd`, a mostly transparent ACP relay in front of a **patched** goose.
It holds goose sessions over HTTP+SSE, keeps a durable per-session log, fans updates
out to any number of WebSocket viewers, and keeps turns, pending permissions and
prompt idempotency across viewer detach, honkd restarts and goose restarts. Then move
pigeon onto it in production.

**Architecture:** honkd routes raw `serde_json::Value` JSON-RPC (design §4). Each held
session is one actor that owns one upstream connection (A4), a durable log at
`<state>/sessions/<sid>.jsonl`, pending server→client requests, and a small pure
turn core. The patched goose (`patched-1.54.0.3`) provides SSE takeover and a replay
ring with `Last-Event-ID`. Because of that, honkd restart = resume every stream from
the last processed goose event id: no reconcile, no epoch change, and viewer cursors
stay valid. The epoch is the upstream **connection generation**. It changes only
when a connection is replaced (activation, re-activation, goose restart, hard
cancel) or the ring reports a gap. Then the log is rebuilt from **export**
(committed, user-visible messages) and viewers get a reset. A long-lived control
connection serves only `session/list` (its conn stream). Every export runs on a
short-lived **side connection**: initialize, subscribe the session stream, export,
DELETE. goose never frees a connection's per-session mailboxes or rings until
DELETE.

**Tech Stack:** Rust 1.99.0 (edition 2024), tokio, axum (`ws`), `honk-upstream`
(reqwest + eventsource-stream), tokio-tungstenite, serde_json, clap, tracing,
tokio-util, fs4 (flock), tempfile. Nix dev shell. GitHub Actions CI.

**Read first:** design §3–§6 and §8; `docs/spike/m0-findings.md` (Summary, A1–A16);
`docs/plans/2026-10-11-goose-patches-plan.md` (wire contract of the three patches,
and its `honk-upstream` task).

## Ground rules

- **honkd requires patched goose.** At startup it reads `Acp-Stream-Features` from a
  `GET /acp` on the control connection. It refuses to start unless that lists both
  `takeover` and `replay`. The exception is `--allow-unpatched-upstream` (degraded
  mode: every reattach is treated as a gap and gets a coarse export rebuild, with no
  precise in-flight recovery).
- **Sandboxes.** Live tests use the patched unit `honk-goose-sandbox-patched` on
  **:4181**. The unpatched `honk-goose-sandbox` on :4180 stays up for comparison and
  degraded-mode checks. **Never restart the patched sandbox**, except in the
  goose-restart exit test (e3), which says so in its doc comment. Production goose
  (:4080) is off-limits until M1b and is author-gated there. `guard_url` refuses 4080
  unless honkd gets `--allow-production-upstream`.
- **Stub-goose processes.** Tests may spawn their own throwaway `goose serve`
  children (Task A1/A2). Each gets an absolute temp `GOOSE_PATH_ROOT`, a temp `HOME`
  and cwd, a random secret and port, and a stub model provider. These are not the
  sandbox units and may be killed freely.
- **Never DELETE an upstream connection to fix a stuck subscriber** (A2). With
  takeover this never comes up. In degraded mode, retry 409 with backoff. DELETE is
  used only for idle eviction, orphan cleanup (A15) and M1c hard cancel. Never send
  `session/close` or `$/cancel_request` upstream (§3, A10).
- **honkd shutdown sends nothing upstream.** SIGTERM behaves like SIGKILL toward
  goose.
- **Persist before acting.** A connection id goes to the state file before its first
  use (A15). A pending request is persisted before fan-out (A8). A prompt's ledger
  entry is persisted before the POST.
- **A log line is appended after its frame is processed.** That applies to **every**
  session-stream frame consumed by any path. Frames that aren't logged
  (responses, server requests) get an id-only line `{"seq":null,"id":N}`. On
  restart, `Last-Event-ID` = the last id on disk. Re-processing a replayed frame must
  therefore be idempotent: the actor drops any frame whose id is ≤ the stream's last
  processed id **before** processing it; pending requests dedupe by id; replies
  dedupe by upstream id.
- **Exports never run on a held or long-lived connection.** Use a short-lived side
  connection, which is DELETEd afterwards (I1).
- **The session actor never awaits recovery.** Rebuild, export, activation and
  degraded-mode 409 backoff run as spawned tasks that report back through the actor's
  channel. The single exception is a takeover re-subscribe on patched goose, which
  answers in under 100 ms and may be awaited inline (I2). The
  actor has explicit states: `Live | Reattaching | Rebuilding | Gone`.
- **Viewer queues are bounded and use `try_send`.** Overflow disconnects the viewer
  (close code 4001), and it resumes from its cursor. SSE readers never wait on
  viewers (A2).
- **Upstream activation passes the stored cwd and `mcpServers: []`** (A5, P3b).
  Viewer-supplied cwds are ignored.
- **Never log request URIs or headers.** The `?token=` query carries the secret.
- **Public repo:** no secrets, org names or `/home/<user>` paths. Use `$HOME` and
  repo-relative paths. Review `--record` output by eye before committing any of it.
- **Tests use a temp `--state-dir`.** Never the default.
- **Long waits:** the bash tool times out at 120 s. Run live tests with a longer
  timeout, or as `systemd-run --user --unit=honk-live-$RANDOM --collect --setenv=PATH="$PATH" …`
  and poll the journal.
- Add dependencies with `cargo add`; don't hand-pin. The code assumes axum 0.8 and
  tokio-tungstenite ≥ 0.26; adapt small API differences and note them in the commit.
- Work on branch `m1`. Commit after every task.

## Downstream contract (M1a)

**Viewer classes.** A WS is **honk-aware** if its `initialize` params carry a
`_meta.honk` object or it sends `session/load`. Otherwise it is **legacy**
(pigeon). Legacy viewers get raw live `session/update` frames (with
`params._meta.honk` stripped), a synthesized `session_info_update` carrying the
current `activeRunId` on attach, and pending requests. They **never** get
`_honk/reset`, replay or rebuilt frames.

| From viewer | honkd |
|---|---|
| `initialize` | Answered locally every time: the cached upstream init result + `_meta.honk = {protocol:1, version, features: ["resume_only"]}` |
| `session/new` | New upstream connection (persisted first). The result is returned verbatim. Auto-attach |
| `session/load` (honk-aware) | Held: log replay (or delta from `_meta.honk.after = {epoch, seq}`), reply, `_honk/replay_done`, pending re-offer, live. Not held: activation, then the same (cold attach is M1c) |
| `session/prompt` | Native semantics (busy error while a run is active). `_meta.honk.client_req_id` is deduped. The reply goes to the originator at turn end and carries `_meta.honk.text` = the turn's assistant text from export. Auto-attach |
| `_goose/unstable/session/steer` | Forwarded verbatim. An unconsumed steer at run end → `_honk/steer_unconsumed` to its viewer (no re-queue in M1a) |
| `session/cancel` | Upstream cancel (remembered if the run isn't announced yet) + every pending request answered `cancelled` |
| Response to a server request | First answer goes upstream; others get `_honk/request_resolved` |
| `session/close` | Detach this WS; reply `{}`; never forwarded |
| `session/list` | Control connection, plus `_meta.honk = {held, running}` per entry |
| Other request with `sessionId` | Forwarded on the session's connection (activating if needed), id remapped |
| Other request without `sessionId` | Control connection |
| `$/cancel_request` | Dropped |

honkd → honk-aware viewers: `_honk/reset {sessionId, epoch}`,
`_honk/replay_done {sessionId, epoch, seq}`,
`_honk/request_resolved {sessionId, requestId, reason}`,
`_honk/steer_unconsumed {sessionId, messageId}`, `_honk/evicted {sessionId}`,
`_honk/gap {sessionId}` (frames were lost mid-run; a reset follows at turn end). Every
logged frame carries `params._meta.honk = {epoch, seq}`.

**Resume-only prompts.** honkd advertises `"features": ["resume_only"]` inside
`_meta.honk` in its `initialize` response. A downstream client recovering after its
own restart may send `_meta.honk.resume_only: true` on `session/prompt` to collect an
existing or in-flight reply without risking starting a new turn. If the prompt's
`_meta.honk.client_req_id` is unknown to honkd (or omitted/unparseable), honkd rejects
the prompt immediately with JSON-RPC error `-32004` (`"unknown client_req_id; resume_only prompt not started"`)
instead of forwarding or starting a new turn.

Error `-32004` means "honkd has nothing for you to collect right now" — it is NOT proof
that the prompt never ran (e.g. the initial prompt may still be in transit or unacknowledged
on a broken socket); downstream clients must NOT auto-resend on `-32004`. Downstream clients
must gate on the features list of EACH connection's `initialize` (a rolled-back honkd or an
upstream goose reached directly silently ignores `resume_only` and would start an unwanted turn).
A collected reply may lack `_meta.honk.text` when honkd could not compute the text
(for instance, following an export transcript failure where the matching user prompt could not be found);
an absent `_meta.honk.text` means "honkd couldn't compute the text", while `_meta.honk.text: ""` (empty string)
means goose ended the turn with no reply text. A client that attached after a restart must treat
missing text as "text unavailable", never substituting its own partial chunk accumulator.
For cold (unheld/evicted) sessions, honkd short-circuits `resume_only` prompts before activation:
it consults the ledger directly, serving a cached `Done` response or returning `-32004` (or `-32602`
for another session's id) with zero upstream `session/load` and zero slot usage.
Clients should only send `resume_only: true` when `resume_only` is present in the advertised
features, and only for re-asks after the client lost its own state (not in-run resends, which may
legitimately be first delivery). honkd treats `resume_only` as set whenever the key is present
and not JSON `false` (so `null`, `0` and `"false"` all mean resume-only); omit the key to mean
"unset". A resume_only request that joins an in-flight or parked prompt can still receive that
prompt's busy error; a client must never fall back to steering on a busy reply to a
resume_only request, since that would inject the text into an unrelated run.

**Implementation notes:**
- Every non-success status bails with
  `anyhow::Error::new(HttpStatusError{op, status}).context(body)`. That covers
  `initialize`, POSTs, the non-409 branch of `subscribe_with`, and DELETE.
- `initialize_with` sends `clientCapabilities: opts.client_capabilities`.
- **Byte stamps.** In the reader, wrap the raw `bytes_stream()` with
  `.inspect(|_| *last_byte_at.lock().get_mut(&key) = Instant::now())` **before** the
  SSE parser. Keepalive comments and empty `data:` lines never reach the parser's
  output, so stamping after parsing would miss them. Set the stamp at subscribe time
  too.
- `Upstream`'s existing `call`/`next` API stays for probes. honkd uses `split()`.

**Failing tests first:**
- `guard_url_with` allows 4080 only with the flag;
- `status_of`/`is_gone` read through a context chain;

- `last_byte_at` advances on a keepalive-only chunk. Feed the reader a stream of

**Stub model** (`stub_model.rs`): an axum server on `127.0.0.1:0` serving
`POST /v1/chat/completions` (SSE when `stream: true`, JSON otherwise) and
`GET /v1/models` (`{"data":[{"id":"stub-model"}]}`). It routes **by request shape,
not FIFO**: goose also makes auxiliary completions (session naming, compaction), so
a plain queue would hand them scripted turns.
- A request is a **turn request** when it carries the session's tools array and its
  last message is a user or tool message. Turn requests pop the next scripted `Turn`.
- Any other request is auxiliary and gets `Text(["ok"])`.
- Tool calls use the tool **name read from the request's `tools` array** (e.g. the
  developer shell tool's exact name), never a hard-coded string. The spike records
  the names.

Scripted turns:

```rust
#[derive(Clone, Debug)]
pub enum Turn {
    /// assistant text, streamed one chunk per SSE event
    Text(Vec<String>),
    /// one tool call (OpenAI `tool_calls` delta). `tool` is matched against the request's

    pub fn apply(&mut self, frame: &Value) {
        match frame.get("method").and_then(Value::as_str) {
            Some(method::RESET) => { let resets = self.resets + 1; *self = Blocks { resets, ..Default::default() }; }
            Some("session/update") => {
                if let Some(c) = frame_cursor(frame) { self.cursor = Some(c); }
                let Some(u) = frame.pointer("/params/update") else { return };
                if let Some(rs) = run_state(u) { self.active_run = rs; }

                    }
                    _ => if let Some(t) = text_of(u) { self.text.entry(key).or_default().push_str(t); },
                }
            }
            _ => {}
        }
    }

        self.order.iter().filter(|k| matches!(k, BlockKey::Text(_))).filter_map(|k| self.text.get(k)).cloned().collect()

    pub fn user_texts(&self) -> Vec<String> {

### Task A5: `honkd::log`: durable per-session log

**Files:** create `crates/honkd/src/log.rs` (unit tests inline).

**File format** for `<state>/sessions/<sid>.jsonl`. Line 1 is the header
`{"epoch":E,"resume_from":K|null}`, where `K` is the session-stream event id the log
starts after, for logs built from export. Every following line is
`{"seq":N,"id":<goose event id>|null,"frame":{…}}` (a logged frame), or
`{"seq":null,"id":N}`. That second form is an **id-only** line, recording that a
session-stream frame which isn't logged (a response or a server request) was
processed (I1). Appends are plain `write_all` of one or more complete lines, **with no
fsync** (ground rule: append after processing; a lost tail is re-delivered by
`Last-Event-ID`). On open, a trailing partial line is truncated.

**The epoch has one source of truth** (`HeldSession.epoch` in `state.json`).
To start a new generation:
1. `next = max(state epoch, existing log header epoch) + 1`;
2. **persist `next` to state**;
3. call `SessionLog::create(next, …)`.

A held session whose log file is missing at startup → rebuild from export as a new
generation.

### Task A6: `honkd::turn`: pure turn core (native prompts, raw steers, cancel)

**Files:** create `crates/honkd/src/turn.rs` (unit tests inline).

**Rules:**
- A native prompt during a run → goose's busy error, synthesized with the run id.
  Nothing is sent upstream.
- A native prompt in the announce window (sent, but no `activeRunId` yet) → parked.
  It gets the busy error once the run is announced, or is dispatched if the inflight
  prompt ends without a run.
- Turn end = `activeRunId:null` **or** the prompt reply. The reply proves the turn
  ended. No timers.
- An early cancel (before announcement) is remembered and re-sent at announcement.
- Raw steers: record `{message_id, viewer}` from the steer reply; a live
  `user_message_chunk` with that id consumes it. Steers still unconsumed at run end
  → `NotifySteerUnconsumed`.

    SendCancel,
    SynthUser { params: Value, owner: OwnerRef },            // honk-aware viewers only (A7: no live echo)
    Reply { owners: Vec<OwnerRef>, body: Reply },            // actor adds _meta.honk.text for Result replies
    NotifySteerUnconsumed { viewer: ViewerId, message_id: String },
}

#[derive(Default, Debug)]
pub struct TurnCore {
    pub run: Option<String>,
    pub inflight: Option<Inflight>,
    pub parked: Vec<(OwnerRef, Value)>,      // native prompts that arrived in the announce window
    pub cancel_pending: bool,
    pub steers: Vec<(String, ViewerId)>,     // raw steers awaiting consumption
}

impl TurnCore {
    pub fn on_prompt(&mut self, owner: OwnerRef, params: Value, ids: &mut crate::rpc::UpstreamIds) -> Vec<Action> {
        if let Some(run) = &self.run {
            return vec![Action::Reply { owners: vec![owner], body: Reply::Error(crate::rpc::busy_error(run)) }];
        }
        if self.inflight.is_some() { self.parked.push((owner, params)); return vec![]; }
        let upstream_id = ids.next();
        self.inflight = Some(Inflight { upstream_id: upstream_id.clone(), owners: vec![owner], params: params.clone(), announced: false });
        vec![Action::SendPrompt { upstream_id, params }]
    }

    pub fn on_run_state(&mut self, run: Option<String>, ids: &mut crate::rpc::UpstreamIds) -> Vec<Action> {
        let mut out = vec![];
        match run {
            Some(r) => {
                self.run = Some(r.clone());
                if let Some(inf) = self.inflight.as_mut() && !inf.announced {
                    inf.announced = true;
                    out.push(Action::SynthUser { params: inf.params.clone(), owner: inf.owners[0].clone() });
                }
                if std::mem::take(&mut self.cancel_pending) { out.push(Action::SendCancel); }
                for (o, _) in self.parked.drain(..) { out.push(Action::Reply { owners: vec![o], body: Reply::Error(crate::rpc::busy_error(&r)) }); }
            }
            None => {
                self.run = None;
                for (message_id, viewer) in self.steers.drain(..) { out.push(Action::NotifySteerUnconsumed { viewer, message_id }); }
                if self.inflight.is_none() { out.extend(self.dispatch_parked(ids)); }
            }
        }
        out
    }

    pub fn on_prompt_reply(&mut self, upstream_id: &str, frame: &Value, ids: &mut crate::rpc::UpstreamIds) -> Vec<Action> {
        let Some(inf) = self.inflight.take_if(|i| i.upstream_id == upstream_id) else { return vec![] }; // replayed/late: idempotent
        if let Some(run) = crate::rpc::busy_run_id(frame) { self.run = Some(run); } else { self.run = None; } // reply ⇒ turn over
        let body = match frame.get("error") { Some(e) => Reply::Error(e.clone()), None => Reply::Result(frame.get("result").cloned().unwrap_or_default()) };
        let mut out = vec![Action::Reply { owners: inf.owners, body }];
        if self.run.is_none() { out.extend(self.dispatch_parked(ids)); }
        out
    }

    fn dispatch_parked(&mut self, ids: &mut crate::rpc::UpstreamIds) -> Vec<Action> {
        if self.parked.is_empty() { return vec![]; }
        let (owner, params) = self.parked.remove(0);
        self.on_prompt(owner, params, ids)
    }

    pub fn on_steer_ok(&mut self, message_id: String, viewer: ViewerId) { self.steers.push((message_id, viewer)); }
    pub fn on_user_message(&mut self, message_id: &str) { self.steers.retain(|(m, _)| m != message_id); }

    /// A9: upstream cancel always; remembered if the run isn't announced yet.
    pub fn on_cancel(&mut self) -> Vec<Action> {
        if self.inflight.as_ref().is_some_and(|i| !i.announced) { self.cancel_pending = true; }
        vec![Action::SendCancel]
    }

    /// A13 goose restart: the run is gone. Never auto-resend.
    pub fn interrupt(&mut self, reason: &str) -> Vec<Action> {
        self.run = None;
        self.steers.clear();
        let owners: Vec<OwnerRef> = self.inflight.take().map(|i| i.owners).unwrap_or_default()
            .into_iter().chain(self.parked.drain(..).map(|(o, _)| o)).collect();
        if owners.is_empty() { return vec![]; }
        vec![Action::Reply { owners, body: Reply::Result(json!({"stopReason":"cancelled","_meta":{"honk":{"reason":reason}}})) }]
    }

    pub fn attach_waiter(&mut self, client_req_id: &str, owner: OwnerRef) -> bool {
        match self.inflight.as_mut() {
            Some(inf) if inf.owners.iter().any(|o| o.client_req_id.as_deref() == Some(client_req_id)) => { inf.owners.push(owner); true }
            _ => false,
        }
    }
}

pub enum SessionMsg {
    // from viewers / hub
    Attach { viewer: ViewerTx, after: Option<honk_wire::Cursor>, reply: oneshot::Sender<AttachSnapshot> },
    AttachLive { viewer: ViewerTx },                        // auto-attach (legacy or first use)

    Steer { viewer: ViewerTx, id: Value, params: Value },
    Cancel,

    ReplyText { owners: Vec<OwnerRef>, body: Reply, text: Option<String> },
}

impl Session {
    pub async fn run(mut self) {
        loop {
            tokio::select! {
                // `events` is the EventRx from Upstream::split(); `up` is the cloneable UpstreamHandle (I2).
                // Frames keep being consumed in every state except Gone: recovery tasks only
                // (re)subscribe through a handle clone; their frames arrive here.
                ev = self.events.recv(), if !matches!(self.state, ActorState::Gone) => match ev {
                    Some(ev) => self.on_upstream(ev),        // sync except quick POSTs (respond / notify)
                    None => break,
                },
                msg = self.rx.recv() => match msg { Some(m) => self.on_msg(m).await, None => break },
                _ = self.watchdog.tick() => self.check_streams(),   // I3, every 5 s
                _ = self.idle.tick() => self.on_idle(),       // Task A16
            }
        }
        self.return_undelivered_to_hub();                     // I8
    }
}
```

When the actor exits (eviction, fatal error), it drains `rx` and sends each
undelivered `SessionMsg` back to the hub, which re-routes it (re-activating if
needed) (I8).

Upstream POSTs that the actor must order (prompt, steer, respond, cancel) are
awaited inline on the handle. They are short loopback POSTs, and the SSE readers are
separate tasks. Anything that waits on goose's *answer* runs in a spawned task that
holds a handle clone and reports back (I1). That means export, load, and a 409
backoff in degraded mode. A takeover re-subscribe on patched goose answers in under
100 ms and may be awaited inline.

**Every upstream event, before anything else** (`on_upstream`, I2):
- **Dedupe.** `Event::Frame(key, frame, Some(id))` with `id ≤ last_processed[key]` is
  dropped. `last_processed[Session]` starts at `log.last_upstream_id()`, and
  `last_processed[Conn]` at `HeldSession.last_conn_event_id`. This makes a replay
  that overlaps already-processed frames harmless.
- **Record.** After processing a session-stream frame: a logged frame →
  `log.append`; any other frame (a response, a server request) →
  `log.mark_processed(id)`. A conn-stream id → `state.mutate(last_conn_event_id = id)`.
  The conn stream is low-rate; batch it if it proves hot.

**Exports never use the held connection or the control connection** (I1).
`hub.export(sid)` opens a short-lived **side connection**: `initialize_with`, persist
its id as an orphan **first** (A15), subscribe the session stream, call export,
DELETE, remove the orphan entry. A crash mid-export leaves an orphan that the next
startup DELETEs. The DELETE only cancels runs started on that connection, and a
side connection never prompts.

**Prompt path** (native only in M1a):
1. Downstream `session/prompt` → hub → actor `Prompt`.
2. Ledger check (Task A14 adds dedupe; here, just route).
3. `turn.on_prompt`.

**Half-open detection** (I3). Every 5 s the actor's watchdog checks
`up.last_byte_at(key)` for both streams. goose sends a keepalive every 15 s, so no
bytes for **20 s** means the stream is dead or half-open (P2d). That triggers a
reattach with takeover. A `StreamEnded` event triggers the same.

**Reattach** (actor in `Reattaching`; on patched goose the takeover GET answers in
under 100 ms and may be awaited inline, while degraded-mode 409 backoff runs in a
spawned task):
- session stream: `subscribe_with(Some(sid), SubscribeOpts { takeover: true, resume_after: Some(log.last_upstream_id().unwrap_or(0)) })`;
- conn stream: `subscribe_with(None, SubscribeOpts { takeover: true, resume_after: Some(last_conn_event_id.unwrap_or(0)) })`.

**Only the session stream's `ReplayOutcome` drives rebuilds.** A conn-stream gap is
logged and otherwise ignored, because nothing on it feeds the transcript. While
`Reattaching`, attaches are served from the log, and prompts, answers and cancels
are queued in the actor (not dropped) until `Live`.
- `Complete` → `Live`. Replayed frames go through the normal path: the dedupe drops
  ids already processed, and the rest are processed for the first time.
- `Gap`, or degraded mode (`Unsupported`): **if a run is active → stay `Live`** and
  keep appending to the current epoch. Send honk-aware viewers a `_honk/gap {sessionId}`
  marker, set `rebuild_at_turn_end`, and do one rebuild when the turn ends. **If
  idle → rebuild now.** There is no mid-run rebuild: the in-flight message isn't in
  export yet, and rebuilding twice per turn buys nothing (I4).
- `is_gone` (404) → `Gone` → Task A17.
- Degraded 409: retry with backoff (100 ms → 5 s), never DELETE.

**Rebuild** (spawned task, actor in `Rebuilding`; frames keep being consumed):
1. `hub.export(sid)` on a **side connection** (Task A9) → `to_updates`, and
   `keys` = their block keys.
2. Report `Rebuilt{frames, keys, resume_from: <last processed session id when the export was requested>}`.
3. The actor starts a new generation (Task A5 epoch rule):
   `SessionLog::create(next, resume_from, export frames as (None, f) ++ frames received during Rebuilding whose key ∉ keys, with their ids)`.
4. Honk-aware viewers get `_honk/reset` + the new log + `_honk/replay_done`. Legacy
   viewers get nothing; they kept receiving live frames throughout.
5. Until the next turn ends, honk-aware fan-out and the log drop live frames whose
   key ∈ `keys`. Committed messages get no further live frames, so these can only be
   retained duplicates.

**honkd restart:** `Hub::start` (A7 step 6) loads `sessions` from state. For each
session: open the log (if it is missing, rebuild as a new generation),
`Upstream::resume_with(conn_id)`, split, initialize `last_processed` from the log
and state, and spawn the actor, which reattaches at once. All handles are
registered before the listener accepts (I8).

**I5 — a restored `inflight` prompt:**
- If the log already contains the reply for that `upstream_id` (a processed
  response is an id-only line, so keep `upstream_id → reply` in a small sidecar,
  `sessions/<sid>.replies.jsonl`, appended **before** the `mark_processed`), finish
  from it.
- Otherwise, with `Complete` replay, **the reply will arrive** if goose ever got the
  prompt, so wait for it. Use export only to answer "was the prompt ever POSTed?":
  no user message with that text after the last processed turn → `cancelled` with
  `_meta.honk.reason: "not_delivered"`, and update the ledger. Present → keep
  waiting for the reply.
- With `Gap` (or degraded mode) and no reply after the turn ends (`activeRunId:null`
  processed), synthesize `end_turn` with `_meta.honk.synthesized: true`. This is the
  only place an end is synthesized, and only when a gap is evidenced.

### Task A16: Activation with stored cwd; idle TTL eviction

**Files:** modify `crates/honkd/src/{hub.rs,session.rs}`; create `crates/honkd/tests/activation.rs`.

**Activation** (spawned task) for a session that isn't held:
1. Find the cwd in `session/list` on the control connection.
2. Create a new connection, persisting its id first.
3. Subscribe both streams (takeover, `resume_after: Some(0)`).
4. `session/load {sessionId, cwd: stored, mcpServers: []}`; **discard its replay
   frames** (C1).
5. Export on a side connection (Task A9) → a new generation per the Task A5 epoch
   rule (`next = max(state or retired epoch, log header) + 1`, persisted first) →
   `SessionLog::create(next, resume_from: last processed session id, export frames)`.
   Frames that arrived on the new connection meanwhile are kept if their key ∉
   export keys (as in a rebuild).
6. The session is now held.

The cached load reply becomes the attach reply. Triggered by: `session/load` from a
honk-aware viewer (M1a; cold attach is M1c), a prompt, an answer, or a forwarded
session method on a not-held session.

**Idle TTL** (A14): a session with no run, no inflight, no pending requests and no
attached viewers for `idle_ttl` →
1. `state.mutate` moves its connection to orphans;
2. DELETE;
3. remove the orphan entry and the session.

The log file stays on disk until the next activation replaces it. The next epoch
number comes from `HeldSession.epoch`, so keep the evicted entry's epoch in a small
`state.retired_epochs: BTreeMap<sid, u64>`.
Never `session/close`. The LRU cap is M1c, but refuse activation beyond
`--max-sessions` with `-32000 "honkd: held-session limit reached"`.

- activation passes the **stored** cwd, not the viewer's (`--idle-ttl-secs 1`: evict,

- after re-activation, honk-aware viewers get `_honk/reset` with epoch + 1 and the
  export transcript;
- a busy session (gated turn) is not evicted;
- eviction DELETEs exactly the idle session's connection.

### Task A17: goose restart (A13)

## Review record (2026-10-11)

The first draft (a692b40) got an adversarial review ("execute after fixes, split")
and a strategic oracle review. The orchestrator adopted the oracle's direction:

- **Patches first; honkd requires patched goose.** Takeover removes the half-open 409
  problem, and the replay ring + `Last-Event-ID` removes at-most-once loss. That
  deleted the reconcile machinery (dirty flags, in-flight carry, boundary
  re-reconciles, quarantine in the tail renderer), the steer-based run-state probe,
  timer-synthesized turn ends and the lost-request heuristic. Unpatched goose is a
  flagged degraded mode.
- **Durable per-session log with goose event ids, and epoch = connection
  generation.** A honkd restart becomes a resume with a delta for viewers, so "no
  duplicated text" holds by construction.
- **Rebuild from export, never from `session/load` replay** (adversarial C1: load
  replay can't be separated from interleaved live frames). The mapping applies
  goose's own user-visible filter.
- **A stub-model spike comes first,** so that most tests run against real goose
  semantics. The fake shrinks to degraded-mode injection.
- **Split into M1a / M1b / M1c.** queue/steer modes, steer confirmation, cold
  attach, LRU and hard cancel moved out of the critical path to pigeon-on-honkd.
- **Folded in adversarial fixes:**
  - viewer classes, so pigeon never sees resets or replays (C2);
  - recovery never blocks the actor (I1);
  - ledger written before the POST, plus a `not_delivered` check (I3);
  - restart-unique `hk<boot>-` ids (I4);
  - smaller tasks, with the turn core wired early (I5);
  - pigeon re-offer on every attach, run state on attach, steer notify-only,
    receipt text in `_meta.honk.text` (I6);
  - state dir bound to its upstream and flocked (I7);
  - handles registered before accept, undelivered messages returned to the hub (I8);
  - rollback by inverse UPDATE (I9);
  - subprocess restart tests; no URI logging; early-cancel replay; ledger session
    check; a live DELETE-frees-parked-run test.
- **Kept:** native prompt default; `?token=` auth; no elicitation advertised;
  pigeon's resend-once with `client_req_id`; refusal on corrupt state; one upstream
  connection per session plus a control connection; never DELETE to evict a stuck
  subscriber; the :4080 guard; author-gated cutover.

### Round 2 (2026-10-11, adversarial review of 84642ce): execute after fixes, no rework

Applied:
- **C1:** restored the `honk-upstream` additions task as **A0.5**, ported to
  `Event::Frame(StreamKey, Value, Option<u64>)`. It covers `initialize_with` caps,
  `resume_with`, `request_with_id`, typed status / `is_gone`, `recv`, `unsubscribe`,
  and a `guard_url_with` opt-in for B3.
- **I1:** exports (turn text, rebuild, activation) run on short-lived side
  connections (initialize, subscribe, export, DELETE), so no per-session mailboxes or
  rings pile up on long-lived connections. Every consumed session-stream frame
  records its id; unlogged frames get id-only lines.
- **I2:** `Upstream::split()` gives a cloneable handle and one actor-owned
  `EventRx`. The actor drops frames with id ≤ the last processed id before
  processing them.
- **I3:** readers stamp `last_byte_at` on raw bytes (keepalives included). A 20 s
  actor watchdog triggers a takeover reattach. The live test uses a frozen
  `TcpProxy`, not SIGSTOP.
- **I4:** a gap during an active run → keep appending in the current epoch, send
  `_honk/gap`, rebuild once at turn end. An idle gap → rebuild at once.
  `SessionLog::create` takes `(Option<u64>, Value)`. Legacy viewers keep getting live
  frames in every state and never see rebuild output.
- **I5:** a restored inflight prompt uses export only to decide "never POSTed"
  (`not_delivered`), and otherwise waits for the replayed reply. `end_turn` is
  synthesized only with an evidenced gap; a reply already processed is read from a
  per-session replies sidecar.
- **I6:** the ring-gap test produces the gap with a frozen proxy (the ring records at
  dequeue only), or injects `Gap` via the fake.
- **Minors:**
  - conn-stream resume uses `Some(id.unwrap_or(0))`, and only the session stream's
    outcome drives rebuilds;
  - `last_conn_event_id` is persisted;
  - the epoch has one source of truth: persist `next = max(state, log header) + 1`
    first, and a missing log means rebuild;
  - replay sends notifications only;
  - A0 uses `HONK_SANDBOX_UNIT`/`HONK_SANDBOX`, a feature check via a GET with a
    connection id, Task 10's release binary, and an autoPatchelf'd `HONK_GOOSE_BIN`;
  - stub env adds `GOOSE_DISABLE_SESSION_NAMING=true` (verified:
    `config/base.rs:1314`, read in `acp/server_factory.rs:101`) and
    `GOOSE_DISABLE_KEYRING=1` (`base.rs:216`);
  - the stub model routes by request shape and reads tool names from `tools[]`;
  - A17 re-checks `Acp-Stream-Features` after a 404.
