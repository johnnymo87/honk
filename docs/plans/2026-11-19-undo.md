# `/undo` and `/redo` in honk chat

Bead: honk-9qf.31.1 (epic honk-9qf.31; study in `docs/plans/2026-11-19-message-history-study.md`,
section D).

## Decisions (Jonathan, 2026-11-19)

1. **Soft.** Undo hides the undone turns and keeps a redo until the revert is committed.
2. **Refuse while busy.** No abort-then-undo.
3. **Only his prompts.** Undo steps back over the human's own prompts; turns started by a
   stall-watch wake, a swarm message, or goose itself are not undo stops (they are hidden or
   deleted along with the human turn they follow).

## Behaviour

- `/undo` (also `:undo`): the revert point moves to the human's latest prompt before the
  current point (or before the end, if none). Everything from that prompt on is hidden in every
  honk viewer, a notice says `undid N turns; /redo to restore` and the composer is filled with
  the undone prompt's text (if the composer is empty). Repeatable.
- `/redo`: moves the point forward to the next human prompt, or clears it (everything back).
- Commit: the revert becomes permanent (goose messages deleted) right before the next prompt
  reaches goose by ANY path through honkd (honk chat, pigeon/Telegram, stall-watch wakes, swarm
  deliveries, steers). After a commit there is no redo. Coordinators get wakes often, so the redo
  window can be short; the notice says so.
- Refused (warning notice, nothing changes) when: a run is active, a prompt is in flight, a
  permission request is pending, the local queue or held steers are non-empty, honkd is
  rebuilding/reattaching, or the target is before a compaction (see Hazards).
- Files are not restored (goose has no snapshots). The notice says so the first time.

## Design (revised after plan review, see end)

### goose (johnnymo87/goose, `patched/v1.54.0` -> `patched-1.54.0.10`)

1. `session/prompt`: if `_meta.goose.messageId` (string) is present, the user message gets that
   id (`server.rs:2373` `convert_acp_prompt_to_message(..).with_id(..)`; kept by `reply_impl`
   `with_generated_id_if_missing`, `agents/agent.rs:2410`, and by every command path,
   `agent.rs:2564-2650`; stored by `add_message`, `session_manager.rs:1943`).
2. New ACP method `_goose/unstable/session/conversation/truncate_from_message`
   `{sessionId, messageId}` -> `{found: bool}` wrapping
   `SessionManager::truncate_conversation_from_message` (`session_manager.rs:571`, boundary
   `(created_timestamp, id)`, no same-second hazard). `found:false` (no-op) when the id is unknown.
   Refuse with an error if the session has an active run. Request/response types in
   `goose-sdk-types/src/custom_requests.rs`, dispatch in `custom_dispatch.rs`.
3. Advertise `truncateFromMessage: true` in `agent_capabilities_meta` (`server.rs:370`); honkd
   enables undo only when it sees it (new honkd on old goose = undo refused, nothing wedges).
4. Tests next to the existing truncate tests.

### honkd

1. **Stable prompt ids.** `TurnCore::on_prompt` and parked prompts (not at POST; `SynthUser`
   reads `inf.params`, `turn.rs:198`) ALWAYS set `_meta.goose.messageId = "msg_honk_<uuid>"`
   (overwrite: truncate deletes from the first row with the id, a duplicate would cut too much).
   The synth user block uses the same id (`session.rs:2424-2428`). Drop goose's echoed
   `user_message_chunk` for the in-flight prompt id (command prompts are echoed,
   `agent.rs:2595` -> `server.rs:1426`), or honk chat would append it (`/compact/compact`).
2. **Undo = log-generation rewrite.** `_honk/undo {sessionId}` through the session actor:
   - refuse unless Live, idle (no run, no inflight, no pending permission, no parked/queued
     prompts) and goose advertised `truncateFromMessage`;
   - export once (cheap, idle). Stops = export user rows whose id starts with `msg_honk_`, that
     are not steers (`metadata`), and that the shared classifier calls human. Target = latest stop
     before the current revert point (or the end). None -> "nothing to undo".
   - compaction guard: refuse if any row at/after the target has `agentVisible == false`
     (catches manual and auto compaction and rolling-memory folds; context_mgmt/mod.rs:149-156,
     rolling.rs).
   - write a new log epoch with the entries before the target's user block; move the tail to a
     redo sidecar (`<sid>.redo.jsonl`); fan out the usual `_honk/reset` + replay. Reply
     `{undone: n_turns, text: <target prompt text>}`.
   - repeat undo pushes further back (sidecar grows at the front).
3. `_honk/redo {sessionId}`: restore the next stop's span (or all) from the sidecar into a new
   epoch; reset + replay. Empty sidecar -> revert cleared.
4. **Revert state** `{target_message_id}` in a top-level `State` map (like `turn_errors`), so it
   survives eviction and honkd restarts. Every new log generation (activation, reattach, gap,
   rebuild_at_turn_end) cuts export frames at the target id while a revert is set
   (`create_new_generation_from_export`, `session.rs:400`).
5. **Commit**, synchronously in `Action::SendPrompt` (`session.rs:2239`; the single path for honk
   chat, pigeon, stall-watch, queued and restored prompts) before the POST:
   `truncate_from_message(target)`; then clear state + sidecar. `found:false` = already
   committed, fine. Any other error: clear the revert anyway, rebuild, warn in a notice, and
   forward the prompt (never block automated prompts). Adjust `client_prompts` and
   `inflight.prompt_index` for the removed prompts so the restart delivery check stays right
   (`session.rs:1361-1365`, `turn.rs:172,341`). Steers never commit (a steer needs an active run,
   which implies no revert); assert.
6. Not adjusted (documented): goose session token totals (context gauge stale until next turn),
   `turn_errors` for an undone failed turn, Telegram posts.

### honk chat

1. `/undo`, `/redo` (+ `:undo`, `:redo`): send `_honk/undo|redo`; reply -> notice
   `undid N turns (files are not restored); /redo restores until the next prompt` and, for undo,
   fill an empty composer with `text`. Error -> warning notice. The reset+replay does the hiding;
   no transcript filter needed. Old honk chat clients get the hidden state via the reset.
2. Shared classifier moves from `tui/quote.rs` to `honk-wire`.

## Hazards / non-goals

- Telegram posts of undone turns are not retracted.
- Undoing a turn that came from a swarm message drops it from the model's context (it is
  inside the hidden range only if it follows the target prompt).
- Viewers that talk to goose directly (not through honkd) see nothing until the commit.
